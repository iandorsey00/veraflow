# 本地工作流自动化

[English](workflow-automation.md)

核流负责准备和校验记录。VeraFlow Integrations 负责对接问卷提供方。本机后台进程定期检查答复文件夹，应用符合条件的答复，并在单独的 Chromium 窗口中填写虚构的就业信息页面。用户负责复核并标记完成。后台进程不会提交目标表单。

## 试用就业信息工作流

请在源码目录中使用 Node.js 24。首次运行前安装依赖和 Chromium。

```sh
npm ci
npx playwright install chromium
mkdir -p "$HOME/VeraFlow-demo-inbox"
scripts/veraflow workflow-worker "$HOME/VeraFlow-demo-inbox"
```

打开后台进程输出的控制台网址。也可在核流桌面版点击 **工作流**，输入输出网址中 `#` 后面的访问密钥。主窗口可以关闭，后台进程须保持运行，电脑须保持唤醒。请勿分享该网址或密钥。

1. 点击 **添加定义**，选择 [employment-workflow.json5](../examples/source/collection/employment-workflow.json5) 和 [employment.vf](../examples/source/collection/employment.vf)。注册时会固定工作流定义及其空白表单的版本。
2. 点击 **创建实例**，再点击 **准备问卷**。将下载的原生请求上传到[私有 Google Forms 控制台](https://github.com/iandorsey00/veraflow-integrations/blob/main/docs/google-forms.zh-CN.md)。在那里发布该问卷，可将答复链接关联到实例。每位答复者应使用独立的实例和请求。
3. 将提供方在 Drive 上的私有答复文件夹同步到后台进程监控的目录。如果同步客户端使用占位文件，请将此文件夹设为离线可用。进行本地测试时，可在核流网页版打开请求并导出离线问卷，然后在控制台导入答复，或将答复保存到监控目录。两种方式均使用相同的原生交换格式。
4. 在第一轮填写虚构姓名、选择 **在职**，并按需填写备注。收到第一轮答复后，再为用人单位与职位准备问卷。若想只测试一轮，可先通过 **补充字段值** 或创建实例时提供姓名、`employed` 就业状态及用人单位。示例接着询问 [answers.json](../examples/source/collection/answers.json) 中的两个字段。
5. 当原始答案恰为 `软件架构师` 时，核流保留原文并将其转换为 `Software Architect`。须用独立来源核验转换后的职位，才可继续自动填写。备注 `可以远程办公。` 会转换为 `Available to work remotely.`
6. 启用自动填写后，后台进程会打开示例网站，填写当前分支字段并读回五项值。点击 **显示已填写页面** 可将该页面置于前台。复核完毕后点击 **标记为已完成**。

Google 控制台已经支持创建草稿、获取答复链接、找回漏收的答复及关闭问卷。请保持管理页面仅所有者可访问。关闭本地请求前，应先从 Google 恢复所有待同步答复。本地关闭会停止接收该请求的新答复。本阶段在提供方创建、发布及关闭问卷仍须手动操作。

## 可移植定义 v1

工作流定义与空白核流表单配对。表单规定字段类型、稳定的字段和选项 ID、校验规则、说明及条件分支。工作流补充收集和目标操作策略。编写时可使用 UTF-8 JSON5 或 JSON，机器交换使用严格的 UTF-8 JSON。重复键与未知属性均视为错误。ID 区分大小写，与显示标题及标签独立。

| 属性                      | 含义                                                                                                                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `format`、`version`       | 固定为 `veraflow-workflow` 和整数 `1`。                                                                                                                                                                                                     |
| `id`、`revision`、`title` | 稳定的工作流 ID、修订 ID 及显示标题。ID 由 1 至 64 个 ASCII 字母、数字、连字符或下划线组成，以字母或数字开头。已注册修订不可覆盖。修改定义或表单时请使用新的修订 ID。                                                                       |
| `scope`                   | 仅指定一个原生范围。用 `{"outputId":"main"}` 选择输出，用 `{"step":0}` 选择从零计数的步骤，用 `{"step":null}` 选择所有输出。                                                                                                                |
| `collection.provider`     | `google-forms` 用于所有者控制台交接，`native-file` 用于原生文件交换和离线问卷。                                                                                                                                                             |
| `sourceMapping`           | 可选的[原生记录映射](record-interoperability.zh-CN.md)，仅在提供来源记录时使用。省略时读取平铺 JSON 或 JSON5。来源字段保留其来源信息。                                                                                                      |
| `transformations`         | 可选规则，以表单字段 ID 为键。每条包含 `kind`、`from`、`to`。当前字段适用，且存储值与 `from` 完全一致时才执行。原生历史会记录原值和转换类型。值发生变化会撤销已有核验。                                                                     |
| `destination`             | `adapter`、稳定的目标 `id`、有序的 `pages`，以及将目标字段 ID 映射到表单字段 ID 的 `fields`。本阶段支持 `playwright-employment`、`fictional-employment` 及 `["intake"]`。字段适用范围随分支变化。多页导航及其外部操作边界由后续适配器实现。 |
| `policy`                  | `autofill` 可为 `automatic` 或 `manual`。 `defaults` 可为 `confirm` 或 `allow-assumed`。 `maxAttempts` 为 1 至 5 的整数。 `completion` 固定为 `human-review`。                                                                              |

选择 `confirm` 时，后台进程将有默认值的字段视为缺失，直到提供实际值。显式留空和未答复沿用原生格式语义。选择 `allow-assumed` 时，核流可采用默认值，导出记录会标明默认来源。翻译和浏览器读回不能代替独立核验。缺失答案、未确定的控制字段、无效值、待核验字段或冲突答复都会阻止记录进入队列。

定义中不要放入凭据、私有记录、认证会话或本机路径。定义可包含公开词条映射，例如示例职位翻译。私有来源记录和工作表单应保存在本机。公开请求只包含问题及选项 ID。收集适配器不需要私有表单或已校验记录。

## 运行与恢复

- 后台进程确认普通 JSON 文件稳定后再读取，定期重新检查整个目录，重启后从磁盘恢复。点击 **重新扫描收件箱** 可立即检查。其他位置的文件可通过 **导入答复** 加入。
- 隔离只记录分类，原文件留在原处。收件箱会显示格式、关联、大小或请求状态问题。修复或重新同步原文件后再扫描。修正后的文件会重新检查。原生 ID 与答案均相同的答复只计一次。ID 相同而答案不同的答复会被隔离。
- 冲突需要明确处理。可导出私有工作表单以对照现有值。选择保留当前值会搁置冲突答复。选择使用收到的答案会应用新值并重新校验，包括受影响字段的独立核验。
- 后台进程使用本机 SQLite 数据库存储固定版本的定义、私有表单及历史、请求关联、接收记录、收件箱诊断和运行尝试。请在单台电脑使用私有本机目录。用 `--state` 或 `VERAFLOW_WORKFLOW_HOME` 可选择独立目录，默认使用当前用户的核流工作流状态目录。备份或删除目录前请先停止后台进程。请保护数据库和原始答复文件，必要时使用操作系统存储加密。数据库记录会一直保留到本地存储被移除。
- **暂停自动填写** 针对一个工作流的所有修订。**停止所有自动填写** 针对整个状态目录。收件箱继续处理。若配置的答复目录无法访问，后台进程会暂停启动新的目标运行。
- 写入前的临时故障可在限定次数内按指数退避重试。如果可能已写入后中断、出现读回差异，或后台进程在运行中退出，请先复核，再明确重试。这里无法保证外部操作恰好执行一次。重启后，已填写实例仍显示待复核。原浏览器页面可能已关闭，可检查后明确启动新的一次填写。
- 控制台仅监听回环地址，检查主机和请求来源，并用每次启动生成的密钥保护数据和操作。浏览器适配器使用隔离环境，仅提供内置的虚构页面。它检查页面身份，通过标签定位控件，读回并核对字段值，最后保留页面等待复核。本阶段不包含真实网站登录、多页导航、API 目标或无人值守提交。

## 命令行和适配器开发

运行 `scripts/veraflow --help` 查看命令。控制台与命令行使用同一个引擎。后台进程启动时会输出控制台网址。操作返回 JSON，`workflow-working-form` 则返回可编辑的核流文档。隔离、冲突、扫描目录不可用或核验不匹配的退出状态为 2，其他命令错误为 1。使用 `--json-errors` 可获取机器可读诊断。

```sh
demo=examples/source/collection
scripts/veraflow workflow-add "$demo/employment-workflow.json5" "$demo/employment.vf"
scripts/veraflow workflow-create employment-intake
scripts/veraflow workflow-status
scripts/veraflow workflow-pause employment-intake on
scripts/veraflow workflow-stop on
```

适配器遵循 [provider.ts](../src/workflow/provider.ts) 或 [destination.ts](../src/workflow/destination.ts) 中与提供方无关的契约。后续的收集适配器只应接收原生公开请求，并返回能通过原生答复解析器的文件。目标适配器接收固定版本的目标配置和已校验记录。请明确检查页面身份及预期字段 ID，写入前检查执行许可，并将写入中断或读回失败视为结果不确定。凭据应保留于适配器自己的本地配置。自动填写适配器不得执行最终提交。

浏览器测试可在不访问线上服务的情况下运行已发布的 Google 适配器。将 `VERAFLOW_INTEGRATIONS_TEST_CHECKOUT` 设为 [VeraFlow Integrations v0.1.0](https://github.com/iandorsey00/veraflow-integrations/tree/v0.1.0) 源码的绝对路径，再运行 `npm run test:ui -- workflow-automation`。测试替身会调用实际适配器创建问卷并导出模拟答复。今后如需在线冒烟测试，请使用私有 Google Forms 和 Drive 账户。

## 实验 11 在线验收

操作者使用 VeraFlow Integrations 0.1.0、在线 Google Forms 和 Drive 同步目录验证了端到端流程。后台进程关联答复，应用无冲突的答案及配置的精确匹配转换，并等待独立核验。首次运行在目标页面填写并读回五个字段，结果全部一致。浏览器保留供人工复核，整个过程没有提交目标表单。

操作者还确认，重复扫描及重命名后的重复答复均未触发再次执行。后台进程停止期间收到的答复，在重启后得到处理。全局停止开关阻止了排队任务，重新启用后恢复执行。两位答复者的记录保持独立。第二次执行的页面可见值已由操作者确认，发布审查时未获得该次运行的内部读回报告。

在线停止开关验收仅覆盖排队任务。正在运行的浏览器操作中断及其他故障场景未在本次在线验收报告中逐项验证。自动化测试单独覆盖模拟 Google 答复导出、关联和重启恢复、暂停与队列状态转换，以及页面布局和读回故障。

后台进程目前从源码目录运行。Google Forms 仍需手动创建、发布和关闭。适配器仅支持内置的虚构就业信息页面。本版本未实现任意网址或多页导航。自动转换使用配置的精确匹配规则。没有关联实例的历史答复会在收件箱记录中标为隔离，原文件保留在原处。
